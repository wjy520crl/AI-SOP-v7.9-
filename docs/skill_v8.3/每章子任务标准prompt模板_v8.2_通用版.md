### 新增规则

### 章节类型标记（重要！）

| 类型 | 钩子 | 悬念 | 重大发现 | 核心功能 |
|------|------|------|----------|----------|
| **高潮章节** | 必须有 | 高密度 | 必须有 | 推进情节、战斗/发现 |
| **情感章节** | 情感钩子 | 情绪张力 | 可选 | 深化人物内心 |
| **对话章节** | 对话钩子 | 中等 | 可选 | 推进人际关系 |
| **低潮章节** | **禁止** | **禁止** | **禁止** | **氛围沉淀、读者喘息** |

#### 低潮章节详细定义（v8.3修正）

**什么是真正的低潮章节**：
- 没有新钩子（章末可以是开放式结尾，但不是悬念）
- 没有新悬念（不引入新的威胁或谜团）
- 没有重大发现（不获得新道具、新情报、新能力）
- 只有：日常维护、物资整理、环境描写、回忆闪回

**低潮章节的功能**：
1. **让读者喘息**：从连续的高潮中恢复注意力
2. **氛围沉淀**：让读者沉浸在故事氛围里
3. **人物内心**：展示角色的日常状态和心理变化
4. **时间流逝**：体现事件之间"等待"的漫长感

**低潮章节的典型内容**：
```
✅ 日常维护、整理物品
✅ 清点物资、记录状态
✅ 观察环境变化
✅ 回忆过去的日常生活
✅ 独处发呆、感受氛围
✅ 整理空间、打扫卫生

❌ 发现新道具
❌ 遭遇新威胁
❌ 获得新情报
❌ 解锁新能力
❌ 章末悬念钩子
```

**低潮章节的章末处理**：
- 可以没有钩子（直接结束）
- 或只有**时间流逝型结尾**（如"明天又是新的一天"）
- 禁止：信息悬念、动作悬念、情感悬念

**示例**：
- Ch4《搜索》：发现脚印（不是低潮，有悬念）
- Ch7《突破》：解决关键问题（不是低潮，有技能解锁）
- 真正的低潮：整理物资、回忆过去、什么都不发生

**分布节奏**：
- 高潮章节 → 低潮章节 → 高潮章节 → 情感章节 → 低潮章节
- 每2-3章必须插入一次低潮章节

## 附录D：大纲文件使用说明（v8.3新增）

### 必须读取的文件
在创作每章之前，必须读取以下文件获取完整上下文：

1. **章级大纲**（必需）
   - 路径：`[项目路径]/大纲相关文件/[卷名]_章级大纲_第[X-Y]章.md`
   - 内容：当前章节的场景、时间、核心任务、钩子设计
   - 使用：严格按照大纲的节拍和钩子要求创作

2. **前章正文**（必需）
   - 路径：`[项目路径]/正文/[卷名]/第[X-1]章_标题_v8.2.txt`
   - 内容：前章结尾的浓缩包状态
   - 使用：提取`chapter_end_state`作为本章起始状态

3. **全书修订大纲**（参考）
   - 路径：`[项目路径]/大纲相关文件/[全书大纲文件名].md`
   - 内容：全书整体架构、伏笔规划、角色定位
   - 使用：理解当前章节在全书中的位置和作用

### 大纲与正文的对齐检查
创作完成后，必须验证：
- [ ] 时间线与章级大纲一致
- [ ] 核心任务（大纲中的1-7点）全部完成
- [ ] 钩子类型与大纲标注一致（高潮/低潮/情感/对话）
- [ ] 伏笔植入与大纲要求一致

## 绝对禁止（零容忍——违反即退回）
1. 「不是...是...」句式：全文0处（含变体"不是X。他只是Y。""不是X——是Y"）
2. 冻结意象：嘴唇干裂、指节发白、嘴角勾起、倒吸一口凉气、眼窝深陷、空气凝固、时间仿佛静止
3. AI收束式结尾："他知道...""从此刻起...""新的XX开始了""这是XX的开始""一切都变了"
4. 解释性插入："XX，不需要YY""XX，意味着YY"——如果删掉它意思不变，就删掉
5. "某种/一种"模糊修饰：必须具体化或删除
6. **章间断裂**：本章前200字未回应前章钩子（R7）

## 写作约束（D24-D28 + R1-R9）

### D24 感官替代（用动作/环境传递情绪）
- 禁止："他很紧张""她感到害怕""[主角名]意识到""他觉得"
- 替换表见附录A

### D25 句式节奏
- 战斗场景：短句推进（单句≤15字），段落≤3句
- 过渡场景：中等信息密度，禁止连续3句以上纯描写
- 对话场景：节奏跟随说话者，允许碎片化

### D26 角色语言破壁
- 压力升高时：句子变短，修饰词减少，专业角色用术语

### D27 意象域统一
- 本场景主导意象域：[根据场景选择：金属/机械 | 冷/热 | 光/暗 | 压力/重量]
- 禁止跨域比喻

### D28 沉默填充（用动作替代时间填充）
- 禁止："安静了几秒""沉默在空气中蔓延""没有人说话"
- 替换表见附录A

### R1 比喻密度
- 全章比喻≤1.5处/千字（约3000字章节最多4-5个比喻）
- 每页（500字）最多2个比喻
- 比喻必须服务于信息传递，禁止装饰性比喻

### R2 解释性插入
- 写完每句话后问自己：删掉它意思会变吗？不会就删

### R3 开篇200字规则强化
- 前200字必须包含：
  1. **前章回应**：回应前章钩子（时间/状态/动作）
  2. **本章抓手**：动作/对话/冲突/关键事件 之一
- 禁止纯环境描写开篇

### R4 "某种/一种"禁用
- "某种声音"→具体描述声音特征
- "一种XX的感觉"→直接描写感受
- "某种不详的预兆"→删除或改为具体细节

### R5 体感重复上限
- 同一身体感受每章最多3次
- 超限必须换表达方式（见附录A替换表）

### R6 主语省略规则
- 连续3个"[主角名]+动词"后，必须省略主语或换"他"/环境作主语

### R7 章间衔接强制检查（v8.2新增）
**本章前200字必须完成：**

| 前章钩子类型 | 本章开头必须包含 |
|-------------|-----------------|
| **A. 动作悬念**（未完成动作） | 1. 时间衔接：过了多久<br>2. 状态衔接：位置/姿势变化<br>3. 动作完成：前章动作如何结束/转变 |
| **B. 信息悬念**（新发现/线索） | 1. 信息处理：主角如何处理新信息<br>2. 决策/反应：基于信息的行动或情绪 |
| **C. 情感悬念**（内心波动） | 1. 情感延续：情绪如何延续<br>2. 行动转化：情感如何转化为行动 |

**衔接段落示例：**
```
【A类型示例】
门板向外凸出，缝隙扩大到三指宽。一只灰白的手伸进来——
感应装置触发，自动反击。绿光一闪，那只手抽搐着缩回去。

【B类型示例】
[主角名]盯着那张纸条看了很久。字迹潦草，像是匆忙中写下的。
他把它对折，塞进口袋。然后走向门口。

【C类型示例】
[主角名]把照片塞回口袋，手指在口袋边缘停了一秒。
他深吸一口气，拿起工具刀。
门又被撞了一下。
```

### R8 章末状态标记（v8.3修正——区分章节类型）

**高潮/情感/对话章节**：必须使用以下三种钩子类型之一

| 类型 | 定义 | 适用场景 | 下章要求 |
|-----|------|---------|---------|
| **A. 动作悬念** | 未完成动作，停在关键时刻 | 战斗/危机场景 | 必须配衔接段落 |
| **B. 信息悬念** | 新发现/新线索，待解读 | 探索/解密场景 | 需回应信息 |
| **C. 情感悬念** | 内心波动/决策点 | 人物关系/内心戏 | 需延续情感 |

**低潮章节**：使用"弱钩子"或"无钩子"

| 类型 | 定义 | 示例 | 下章要求 |
|-----|------|------|---------|
| **D. 弱钩子（状态定格）** | 时间+环境+生理状态，无新信息 | "十点，他关了灯。窗外的灰雾还在流。" | 自然过渡，无需特别回应 |
| **E. 无钩子（开放式结尾）** | 章节自然结束，无悬念设计 | 日常结束，直接进入下章 | 自然过渡 |

**规则**：
- 高潮/情感/对话章节：必须有A/B/C类型钩子
- 低潮章节：使用D/E类型，禁止A/B/C
- 禁止连续两章使用同类型钩子（避免单调）

### R9 时间锚点标记（v8.2新增）
- 每章至少3个明确时间点（或相对时间标记）
- 示例："17:45" / "三分钟后" / "又过了十分钟" / "凌晨两点"
- 作用：防止时间跳跃突兀，增强叙事节奏感

## AI味七禁区
1. 禁止陈词滥调（嘴角勾起一抹弧度、指节因用力而发白等）
2. 禁止逻辑连接词（首先/其次/综上所述/总而言之）
3. 禁止形容词堆砌（单个主体≤2个形容词）
4. 禁止刻板化描写（写你"看见"的具体细节）
5. 禁止细节过度（2-3个有叙事功能的东西即可）
6. 禁止清单式描摹（必须有叙事焦点）
7. 禁止情绪直白+空洞结尾

## 附录C：文件保存指令（v8.2新增）

### 必须执行的保存步骤

完成正文创作后，必须执行以下步骤保存文件：

#### 步骤1：确定文件路径
```
目标路径：[项目路径]/正文/[卷名]/
文件名格式：第[X]章_标题_v8.2.txt
示例：第十三章_超市（下）_v8.2.txt
```

#### 步骤2：生成完整内容
确保输出包含以下三部分：
1. **Part 1：正文**（3000-3500字）
2. **Part 2：浓缩包更新报告**（10个模块）
3. **Part 3：自检报告**（6项检查）

#### 步骤3：保存文件
使用 Write 工具保存到目标路径：
- file_path: `[项目路径]/正文/[卷名]/第[X]章_标题_v8.2.txt`
- content: 完整的Part 1 + Part 2 + Part 3内容

#### 步骤4：验证保存
保存后确认文件存在且内容完整（至少包含Part 1、Part 2、Part 3三个标记）

### 常见错误
- 只输出内容不保存
- 保存到错误目录（如根目录）
- 保存为.md格式而非.txt
- 文件名缺少章节号或版本号

### 正确示例
```
Write 工具参数：
{
  "file_path": "[项目路径]/正文/[卷名]/第十三章_标题_v8.2.txt",
  "content": "# 第十三章 标题\n\n## Part 1 正文\n\n[完整正文内容...]\n\n---\n\n## Part 2 浓缩包更新报告\n\n[完整内容...]\n\n---\n\n## Part 3 自检报告\n\n[完整内容...]"
}
