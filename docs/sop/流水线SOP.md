# 小说流水线SOP v7.9

> 更新：2026-05-12
> 当前版本：v7.9
> 最近更新：文学质感升级（D24-D28五条创作指导原则）

---

## 核心原则

1. **大纲是唯一的锚**——不进请求=给主笔自由发挥空间=必偏
2. **Agent做专业的事，我只做调度**——不替Agent写、不替Agent审
3. **偏好文件前置**——每个Agent有自己的偏好文件，一开始就避免犯错
4. **每章开新session**——主笔不保持 session，防止上下文爆炸导致产出字数递减（实测：保持session时第3章~2100字→第4章~1500字；新session后第5章恢复至~3200字）
5. **进度透明——非阻塞式汇报**——spawn 子代理后立即主动汇报启动状态，不冻结等待。用户可随时询问进度，子代理完成后 push 通知。
6. **安全网 + 偏差层 + 柔性层 + 被动接收层（v7.2 新增）**——被动接收层通过信息包装度检测（D22）识别叙述者信息裸奔段落，触发1.8.x指令强制将信息通过角色对话/动作/决策间接传递，降低阅读摩擦。
7. **工具强制拦截优先于人工检查**——所有可自动化检测的项目（冻结意象/句式模板/章节号引用/参数连珠炮）必须先经过sop_scanner.py扫描，人工仅复核扫描器遗漏的语境问题。
8. **时间锚点锁定（v7.6 新增）**——每次提及"X年前"等时间表述时，必须grep浓缩包`time_anchors`区块确认一致性；`locked: true`的时间点不可随意修改，修改时需全局搜索并同步更新所有引用。
9. **物象状态变更必须有观察者（v7.6 新增）**——物象的任何可见特征改变（颜色/亮度/完整性/位置）必须在`physical_anchor_items.status_change_log`中记录，且必须包含`observer`字段（哪位角色观察确认）和`quote`字段（原文引用）。
10. **带伤行动必须核对时间线（v7.6 新增）**——角色带伤参与战斗或高强度行动时，必须核对`character_registry.injury_record`中的恢复时间；若时间跨度不足恢复期，必须显式解释（如"医疗舱加速愈合""义体替换"等）。

## 二、新增维度定义（v6.9 + v7.1）

> v6.9来源：《我在异界当反贼》蓝本提炼。在v6.8.4的12维度基础上，新增7个维度（D13-D19），覆盖长篇连载的结构性需求。
> v7.1新增：D20情感压强审计、D21配角辨识度审计，解决情感过载与群像记忆点单一问题。

### 2.2 维度详细定义

**D13：支线缠绕度**
- 追踪每一条活跃支线（在浓缩包 `active_subplots` 中维护）
- 推动标准：新能力获取(+1) / 新盟友/敌人确立(+1) / 关键资源变化(+1) / 主线危机升级/缓解(+1)
- 触发：某支线连续10章累计推动为0，下一章必须安排该支线与主线的强制交叉

**D14：主角道德灰度（v7.0 优化）**
- 灰度行为类型：情感驱动的非理性决策 / 道德妥协（为更大目标牺牲小原则）/ 个人牺牲（为他人承担本可避免的损失）
- **道德基线动态漂移（v7.0 新增）**：主角行为准则随成长阶段变化。隐忍期（生存优先，可接受高妥协）→ 积累期（建立原则，不排斥灰色手段）→ 爆发期（强力守护阵营，对敌无情）→ 成熟期/统治期（大局观，考虑更广泛后果）。
- **检测逻辑**：参照当前阶段 `moral_baseline`（浓缩包维护），检测最近10章主角行为是否与当前基线一致。只有在行为持续偏离当前基线时（如爆发期仍做出隐忍期的软弱行为），才触发灰度场景。
- 触发：连续10章行为未体现当前阶段应有特征，强制下章安排体现该阶段核心矛盾的灰度场景。

**D15：对手智能审计（v7.0 优化）**
- 检测内容：对手策划智力 ≥ 设定智力×80%？主角计策有无被对手部分识破？对手有无主动布局？
- **计策通用性评估（v7.0 新增）**：反制手段是否可独立于主角计策存在？如果对手不出于反制主角的目的，这种布局/行为是否依然可能出现？是→通用性高（优秀）；否→低级反制（及格）。
- 触发：连续3章对手无有效抵抗或仅为"低级反制"，触发噪音投放（更倾向1.3.1第三方介入或1.3.5环境突变，避免强行反制降智）。

**D16：物象载体（v7.0 优化）**
- 物象类型：传承物（武器/徽章/书信）/ 牺牲代价（伤痕/缺失/遗物）/ 约定印记（暗号/标记/留言）
- **物象状态变化监测（v7.0 新增）**：追踪 `physical_anchor_items` 中活跃物象的状态变化（断裂/遗失/赠予/被毁）。状态变化等同于新增物象的叙事价值。
- 触发：5章内既无新物象生成，也无活跃物象状态变化，触发物象植入指令（优先推荐会发生状态变化的物象或安排旧物象消亡/传承）。

**D20：情感压强审计（v7.1 新增）**
- **定义**：追踪文本的情感压强分布，防止连续性高压导致读者感官疲劳。
- **压强等级定义**：
  - **低（L）**：日常描写、环境铺陈、技术说明、非冲突性对话。
  - **中（M）**：带有紧张感的决策、备战、轻度冲突、任务的推进。
  - **高（H）**：直接对抗、重大威胁、时间压力、强烈情绪爆发、死亡风险。
- **检测算法**：
  1. 将本章按自然段划分为连续单元，每单元标注情感压强（L/M/H）。
  2. 计算本章的"高压连续长度"：最大连续H段落数 ÷ 总段落数。
  3. 扫描全文，检测是否存在"换气点"——即在高H密度区域之间，是否存在L或低M的段落插入。
- **阈值设定**：
  - 连续高压段落数 > 总段落数×15% → 黄色警告。
  - 黄色警告且结尾前（最后20%内容）未出现任何L级段落 → 红色，强制触发情感换气。
- **触发动作**：
  - 黄色：建议在下一章的决策或对白段落中插入一个低压场景（个人回忆、环境凝视、日常碎片）。
  - 红色：强制在高压区域之间插入150-300字的L级"换气点"。

**D21：配角辨识度审计（v7.1 新增）**
- **定义**：追踪每个常驻配角（非一次性龙套）的"记忆点"类型，确保其出场时的描写不单一模板化。
- **记忆点类型分类**：
  - **口语习惯**：特定口头禅、语气词、说话节奏、方言痕迹。
  - **标志性动作**：习惯性手势、肢体语言、工作方式、战斗风格。
  - **视觉特征**：疤痕、纹身、服装细节、体态、器物。
  - **个人史碎片**：被简略提及但未展开的过往细节、独特经历、不为人知的秘密。
- **检测逻辑**：
  1. 维护常驻配角列表，每人分配一个`memory_point_history`数组。
  2. 提取该配角每次出场时，作者投入的"新记忆点"及类型。
  3. 追踪该配角最近3次出场的记忆点类型分布。
- **阈值设定**：
  - 最近3次出场中，同一类型记忆点占比 > 66% → 黄色警告。
  - 连续3次出场均使用完全相同的记忆点（如每次都是"他在算"）→ 红色，强制触发多样化指令。
- **触发动作**：
  - 黄色/红色：在下一次该配角出场时，此角色配置不同类型记忆点（若前三次都是"标志性动作"，此次优先分配"个人史碎片"或"口语习惯"）。

**D23：跨章重复检测（v7.3 新增，v7.5 阈值收紧）**
- **检测范围**：
  1. 意象重复（原有）
  2. 句式模板重复（v7.3新增）——检测"嘴角动了一下""手指攥紧"等模板
  3. 章节号引用核对（v7.3新增）——检测"第X章"引用是否与实际章节匹配

- **检测算法**：
  扫描当前章节，对句式模板库中的每个模板进行匹配计数：
  - v7.5阈值收紧：每章最多2次同类模板
  - 匹配次数 > 2 → 黄色警告，触发替换指令
  - 匹配次数 > 4 → 红色，强制变化表述

- **替换模板库（v7.5 新增）**：
  | 原模板 | 替代表达 |
  |:---|:---|
  | 手指敲 | 每章≤10次，超限替换为：拇指摩挲 / 手掌按在 / 拳头攥紧 / 指甲抠进掌心 |
| 手指停 | 每章≤10次，超限替换为：指尖悬在半空 / 手僵住了 / 动作顿住 |
| 手指收紧 | 每章≤10次，超限替换为：指节用力到发白 / 掌心攥出汗 / 手指绞在一起 |
| 沉默了 | 每章≤10次，超限替换为：没说话 / 没接话 / 没再说话 / 停顿 / 过了几秒 |
| 安静了 | 每章≤10次，超限替换为：没人接话 / 气氛沉下来 / 声音断了 |

- **章节号引用验证**：
  提取文本中所有"第X章"引用，与实际章节编号比对：
  - 引用不存在 → 红色，强制修正
  - 引用与当前章节相同 → 黄色，建议删除（无需引用自己）

## 四、偏差指令库（v6.9）

> **设计原理**：AI倾向于"安全模式"——均衡、对称、规律化。偏差指令库作为"可控破坏器"，在保持逻辑连贯的前提下，对特定维度强制施加不对称、不完美、不规则的处理。
> **使用规则**：每章最多激活1个偏差指令组；同一指令组内模块最多叠加2条；偏差日志需记录激活的模块编号和效果评分。

### 4.1 感官禁闭指令组

**目标**：打破视觉为主、触觉听觉辅助的感官描写惯性。

| 模块 | 名称 | 适用状态 | 核心规则 |
|:---|:---|:---|:---|
| 1.1.1 | 听觉禁闭 | 爆炸震聋/真空/静音结界/情绪失聪 | 禁用所有声音描写；对话改为读唇语、触觉传递、手势 |
| 1.1.2 | 触觉禁闭 | 室内对话/战略会议/回忆场景 | 禁用材质质感、疼痛身体描写；用动作反应暗示 |
| 1.1.3 | 嗅觉剥夺 | 任何场景 | 禁用地气描写及气味引发的情感联想；用视觉替代 |
| 1.1.4 | 视觉禁闭 | 完全黑暗/烟雾/失明 | 禁用颜色/形状/光影；强化听觉回声定位+触觉材质辨别 |
| 1.1.5 | 双感禁闭 | 高难度场景（仅关键章） | 同时禁闭任意两种感官，极端强调剩余感官 |

### 4.2 对话失衡指令组

**目标**：打破群戏中"公平轮流发言"的模板化对话模式。

| 模块 | 名称 | 核心规则 |
|:---|:---|:---|
| 1.2.1 | 对话垄断者 | 指定某角色占≥70%台词；其他角色沉默服从/单字回应/沉默反抗/试图插话被压制；结尾垄断被打破 |
| 1.2.2 | 沉默核心 | 指定重要角色在本章完整场景中只说话1次（或不说话）；通过他人提及+动作描写+沉默成为焦点保持存在感 |
| 1.2.3 | 断裂式对话 | 关键对话被外部事件/理解偏差/突然截断打断至少3次 |
| 1.2.4 | 观察者视角对话 | 群戏只从非参与者外部视角描写；只听不说；对话内容通过"碎片摘取"呈现 |
| **1.2.5** | **话题悬置** | **v7.0 新增**。本章由某角色提出至关重要的问题（主线秘密/人物关系/未来危机），因外部事件被搁置。问题记录到浓缩包 `pending_questions`。至少2章后由同一角色或受影响角色重提，迫使面对。单章最多1次 |

### 4.3 噪音投放指令组

**目标**：打破主角计划"顺利推进"的惯性，增加不可预测性。

| 模块 | 名称 | 投放时机 | 投放内容 |
|:---|:---|:---|:---|
| 1.3.1 | 第三方介入 | 主角付出重大牺牲/苦战后精神松懈、自以为掌控全局时 | 全新势力/角色突然出现，干预事件走向 |

### 步骤1-3 spawn 通用规范（v6.8.2 新增）

**任务长度限制**：`task` 参数 ≤800 tokens。超出时用 `attachments` 传文件，或让子代理自行 `read` 读取。禁止把完整写作偏好/质检标准塞进 `task`。

**超时容错策略（CKP-1b）**：
```
spawn → runTimeoutSeconds=300
  ├─ 正常完成 → 进入 CKP-1a（常规验证）
  └─ timeout → 不立即判定失败
      ├─ glob_search 检查 workspace 预期文件是否已落盘
      │   ├─ 文件存在且字数>1500 → 视为成功，跳过 CKP-1a
      │   └─ 文件不存在/损坏 → 重试1次（runTimeoutSeconds=600）
      └─ 重试仍失败 → 调度者 fallback / 通知用户
```

> **教训（Ch23）**：墨笔首 spawn 状态显示 timeout，但文件实际已落盘（11,007 bytes）。若按状态判定失败会误杀成功产物。

**进度汇报机制（v6.8.2 修正）**：

OpenClaw 子代理架构下，主会话在子代理运行期间无法主动推送消息。采用**非阻塞式调度**：

```
调度者 spawn Agent → 立即汇报用户
  "【ChX 流水线】步骤N [Agent名] → ⏳ 已启动，预计3-5分钟"
    ↓
  调度者**不**调用 sessions_yield 长时间冻结
    ↓
  子代理后台运行期间：
    - 用户随时可询问进度 → 调度者响应式检查并汇报
    - 子代理完成后 → push 通知调度者 → 调度者汇报结果
    ↓
  子代理完成/失败后：
    "【ChX 流水线】步骤N [Agent名] → ✅ 完成 | 下一动作：..."
```

**禁止行为**：
- ❌ 调用 sessions_yield 后冻结数分钟，用户无响应
- ❌ 等用户问了才回复（被动回复模式）
- ✅ spawn 后立即主动汇报启动状态
- ✅ 子代理完成后主动汇报结果（如收到 push）

> **教训（Ch23/Ch24）**：调用 sessions_yield 后，子代理运行期间主会话冻结，用户发"咋样了"才唤醒调度者，体验极差。改为非阻塞式后，用户始终知道流水线在跑。

### 步骤2.4：强制扫描检查（v7.3 新增）

**目的**：在AI味审计之前，先用自动化工具拦截硬约束违规。

**执行清单**：

| 检查项 | 工具 | 阈值 | 不通过动作 |
|:---|:---|:---|:---|
| 冻结意象扫描 | grep | 出现≥1处 | 列出所有匹配行，强制替换 |
| 「不是...是...」计数 | grep | >0处/章（零容忍） | 列出所有匹配行，强制删减（含"不是X——是Y"破折号变体） |
| 参数连珠炮检测 | 正则匹配 | 连续3句含数字 | 标记位置，触发1.8.1 |
| 句式模板重复 | 模板匹配 | 每章≤10次 | 超过阈值建议变化 |
| 章节号引用 | 数字提取+比对 | 引用≠实际 | 红色，强制修正 |

**冻结意象清单**：
- 指节发白、嘴角勾起、倒吸一口凉气、眼窝深陷、嘴唇干裂
- 空气凝固、时间仿佛静止
- 折叠椅铁管硌肩胛骨、座椅弹簧硌后背

**句式模板库**：
- "嘴角*了一下"（嘴角动了一下/嘴角扯了一下/嘴角抽了一下）
- "手指*紧"（手指攥紧/手指攥住）
- "手指*敲"（手指在XX上敲了敲）
- "手指*停"（手指停在XX上）
- "手指*收紧"（手指收紧）

### 五步检查法（v6.9 升级）

#### ① 交叉验证（必做）

质检报告的硬约束#1数值 vs `grep "不是"` 独立计数。

```
差值 = grep数 - 质检数
差值 ≥ 2 → 🔴 质检Agent漏检严重，标记为"质检可靠性下降"
差值 = 1 → 🟡 可接受偏差
差值 = 0 → 🟢 质检可靠
```

若差值 ≥ 2，记录：第X章、质检数、实际数、漏检率。累积≥3章 → 触发规则D。

#### ② 漏检追踪（有人工修复时执行）

对比人工修复内容 vs 质检报告：

| 问题 | 在质检报告中？ | 处理 |
|:---|:---|:---|
| 质检报告列了 → 已修复 | ✅ | 记录修复方式 |
| 质检报告列了 → 未修复（人工改的别处） | ✅ | 追溯为什么质检标记了但没改 |
| 质检报告**没列** → 人工发现了 | ❌ 漏检 | **重要**：记录漏检类型、根因 |
| 质检报告**没列** → 人工也没发现 | ❌ 盲区 | 记录发现途径、为什么盲区 |

#### ③ 趋势分析（每3章汇总一次）

回溯近3章自进化日志，找模式：

| 模式 | 判定 | 动作 |
|:---|:---|:---|
| 同一硬约束连续2章触发 | 主笔/台词需针对性调整 | 更新写作偏好 |
| 同一漏检类型连续2章出现 | 质检Agent检测盲区 | 更新质检标准 |
| 同一人工修复操作重复3次+ | 应固化为SOP规则 | 更新SOP |
| 字数连续2章不达标 | 浓缩包/大纲信息量不足 | 检查输入质量 |
| AI味指数连续2章 > 60 | AI味审计触发效果不足 | 增加偏差指令强度或频率 |

#### ⚠️ 方向检查（趋势分析触发动作前，必做）

> **教训（Ch8→Ch9）**：进化动作指向下游而非上游，同类问题复发。

趋势分析触发动作前，先定位问题源头（上游/中游/下游），确保进化动作指向正确方向。**铁律**：上游先行（下游加固是兜底，不替代上游修正）。

#### ④ 规则有效性（有模式时执行）

检查：规则最近3章是否触发（未触发→是否不适用？）、新问题是否缺规则覆盖、阈值是否合理、偏差指令频率是否合理。过度执行检测（v6.6）：连续5章🟢且五步全绿→系统成熟，考虑精简模式。

#### ⑤ 编辑端增量检查（必做）v6.5 新增

> **教训（Ch14→Ch15）**：编辑优化中可能新增违规（做加法），传统交叉验证无法区分"初稿即有"和"编辑新增"。

**每章必做**：对比主笔初稿grep vs 编辑版grep。`编辑增量 ΔF = F₂ - F₁`

| ΔF | 信号 | 动作 |
|:---|:---|:---|
| < 0 | 🟢 编辑做减法 | 记录修复质量 |
| = 0 | 🟢 编辑无影响 | — |
| = +1 | 🟡 边界新增 | 检查是否为重构笔误 |
| ≥ +2 | 🔴 编辑系统性引入 | **调整步骤2硬约束** |

#### ⑥ AI味指数追踪（v6.9 新增）

**输入**：步骤2.5 AI味审计报告。记录本章AI味指数（0-100）、触发指令清单、近3章趋势。

| AI味指数 | 信号 | 动作 |
|:---|:---|:---|
| 0-30 | 🟢 优秀 | 记录最佳实践 |
| 31-50 | 🟢 良好 | 维持当前策略 |
| 51-60 | 🟡 偏高 | 检查偏差指令执行 |
| 61-75 | 🔴 高AI味 | 下章强制激活至少1个偏差指令 |

趋势：连续3章上升→🔴系统性审查；连续5章≤30→🟢可降低偏差指令频率。

#### ⑦ 偏差指令效果评分（v6.9 新增，有激活偏差指令时执行）

**评分方法**：`效果评分 = (激活前AI味 - 激活后AI味) / 激活前AI味 × 100% + 叙事连贯性补偿(±10分)`

| 效果评分 | 信号 | 动作 |

| > 30% | 🟢 有效 | 记录为有效模块 |
| 10%-30% | 🟡 边际有效 | 尝试组合其他模块 |
| < 10% 或负值 | 🔴 无效或破坏 | 分析原因，调整或弃用 |

**记录位置**：浓缩包 `deviation_log` + 自进化日志。

## 附录12：SOP变更纪律

每次修改SOP时，必须同步执行：

1. **去重检查**：新规则是否与已有规则重复？重复则合并
2. **归档检查**：是否有旧规则可以被删除或合并？
3. **版本日志**：只保留最近3条更新记录
4. **扫描器同步**：如果新增了可自动检测的规则，同步更新sop_scanner.py
5. **模板同步**：如果修改了浓缩包字段，同步更新浓缩包模板文件

**禁止：只做加法不做减法**

## 附录13：每5章文学质感审查清单

每完成5章后，执行以下人工审查：

```
第X-X+4章文学质感审查：

□ 直白情绪词检查
  grep "很紧张\|很愤怒\|很害怕\|感到恐惧\|觉得不安\|非常担心" → 应为0

□ 比喻域检查
  标记所有"像..."比喻，确认都在四域内（金属/机械、冷/热、光/暗、压力/重量）
  跨域比喻（如"热带雨林般潮湿"）→ 删除或改写

□ 沉默填充统计
  统计"安静了\|沉默了\|没人说话\|没人接话"出现次数
  5章合计应≤15次（平均3次/章）
  超标→用动作填充替换

□ 开篇方式检查
  连续3章不能用同一开篇方式（环境/对话/动作/独白）

□ 钩子类型检查
  连续3章不能用同一钩子类型（悬念/信息/决策/情绪）

□ 环境入口检查
  连续3章不能用同一入口顺序（光→声→气味→动作）
```
