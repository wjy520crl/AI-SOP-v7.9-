## 一、审计工作流

```
[步骤1 主笔初稿] → [步骤2 台词优化] → [步骤4.5 AI味审计 v1.0] → [输出审计报告] → [触发偏差指令] → [局部改写/标记] → [步骤3 质检]
```

**执行者**：调度者（Friday）直接执行，不依赖 Agent。
**输入**：编辑版全文（步骤2输出）。
**输出**：审计报告 + 触发指令清单。
**耗时**：纯文本分析，≤ 1分钟。

## 二、六维度审计标准

### 维度一：沉默描述检测

**检测对象**：所有包含以下关键词的段落——
`沉默、不说话、安静、没有回答、默然、无言、不语、沉寂`

**检测算法**：
1. 提取所有沉默类段落（含关键词前后各1句）
2. 对每段提取后文2句内的伴随描写
3. 归类为五类：
   - A. 手部动作（攥拳、松手、指尖、握手、拍肩等）
   - B. 眉眼变化（垂眼、抬眸、皱眉、眼神、目光等）
   - C. 呼吸气息（深呼吸、屏息、气息、呼吸声等）
   - D. 身体姿态（僵住、后退、转身、站立、坐下等）
   - E. 外部环境（风声、灯光、时间流逝、远处声音等）
4. 计算占比

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 手部动作占比 ≤ 40% 且 前三类(A+B+C)占比 ≤ 60% | 无需处理 |
| 🟡 黄色 | 前三类占比 60%-80% | 记录警告，下一章关注 |
| 🔴 红色 | 手部动作占比 > 40% 或 前三类占比 > 80% | 触发感官禁闭 1.1.2（触觉禁闭） |
| 🔴🔴 严重 | 连续2章红色 | 触发双感禁闭 1.1.5 |

---

### 维度二：感官分配检测

**检测算法**：
1. 对每句描写进行感官标签（每句只标主感官）：
   - 视觉：颜色、形状、光影、视野、外貌、场景
   - 听觉：声音、音量、音色、对话、环境音
   - 触觉：温度、质感、疼痛、触感、气流
   - 嗅觉：气味、香气、臭味、血腥味
   - 味觉：味道、苦涩、甘甜、血味
2. 统计各感官的描写句数
3. 计算占比的方差

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 方差 > 阈值（视觉占比 35%-65% 之外有其他感官显著分布） | 无需处理 |
| 🟡 黄色 | 方差 ≤ 阈值，但非连续 | 记录警告 |
| 🔴 红色 | 连续2章方差 ≤ 阈值（感官分配过于均衡） | 触发感官禁闭（禁闭占比最高的感官） |
| 🔴🔴 严重 | 连续3章方差 ≤ 阈值且各感官占比完全一致 | 触发双感禁闭 1.1.5 |

> **方差阈值参考**：5种感官占比的标准差 < 8% 视为"过于均衡"。

---

### 维度三：对话对称检测

**检测算法**：
1. 提取群戏场景（≥3人同时出现的对话段落）
2. 计算每个角色的发言字数
3. 计算：
   - 标准差 / 均值 = 离散系数
   - 最大值 / 最小值 = 极值比

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 离散系数 > 25% | 无需处理 |
| 🟡 黄色 | 离散系数 15%-25% | 记录警告 |
| 🔴 红色 | 离散系数 < 15%（发言量过于平均） | 触发对话失衡 1.2.x |
| 🔴🔴 严重 | 极值比 < 2（最活跃与最沉默角色发言量差距<2倍） | 强制触发 1.2.1 对话垄断者 |

---

### 维度四：比喻重复检测（v7.0 增强）

**检测算法**：
1. 提取本章所有比喻句（含"像、如同、仿佛、似、好比"等喻词）
2. 提取喻体（比喻中的客体）
3. 为每个比喻标注意象域（战争与兵器/自然现象/死亡与幽冥/精密机械/腐败与毒物/光影与火焰等）
4. 查询跨章比喻喻体数据库（浓缩包 `physical_anchor_items` + 历史审计报告）
5. 检测新章比喻是否与数据库重叠

**阈值与动作（喻体重复）**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 间隔 > 10章 | 无需处理 |
| 🟡 黄色 | 间隔 5-10章 | 记录警告 |
| 🔴 红色 | 间隔 < 5章 | 标记需修改 |
| 🔴🔴 严重 | 间隔 < 3章 | 强制替换，喻体加入黑名单（冷冻20章） |

**新增：意象域一致性检测（v7.0）**

1. 统计最近3章比喻的意象域分布
2. 若连续3章超过50%的比喻属于同一意象域 → 🟡 黄色警告
3. 强制下章引入来自不同意象域的喻体

> **喻体数据库维护**：每章审计后将新喻体追加到 `novel_creator/archives/比喻喻体数据库.md`，格式：`喻体 | 首次章号 | 最近章号 | 使用次数 | 意象域`

---

### 维度五：钩子类型轮换检测

**检测算法**：
1. 识别每章章末钩子类型（8种）：
   - T1 存亡危机、T2 悬而未决、T3 时限赌注、T4 信息差
   - T5 代价展示、T6 身份揭露、T7 误解、T8 绝境宣言
2. 统计各类型连续出现次数

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 未连续出现 | 无需处理 |
| 🟡 黄色 | 连续2章同类型 | 记录警告 |
| 🔴 红色 | 连续3章同类型 | 强制轮换（下一章必须换类型） |
| 🔴🔴 严重 | 连续4章及以上同类型 | 触发钩子重写 + 1.4.4 反向节奏 |

---

### 维度六：开篇方式检测

**检测算法**：
1. 识别前200字的开篇方式：
   - A. 对话开篇（角色开口说话，以"或'开头）
   - B. 冲突/动作开篇（战斗/追逐/紧急行动/突变）
   - C. 环境描写开篇（天气/场景/氛围/景物）
   - D. 心理独白开篇（内心活动/回忆/反思/感受）
   - E. 设定陈述开篇（背景介绍/规则解释/世界观）
2. 统计各类型连续出现次数

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 开篇为A对话 或 B冲突/动作 | 无需处理 |
| 🟡 黄色 | 开篇为C环境描写 | 记录警告 |
| 🔴 红色 | 开篇为D心理独白，或连续2章C环境描写 | 标记需改写 |
| 🔴🔴 严重 | 开篇为E设定陈述，或连续3章C/D | 触发 1.4.4 反向节奏 或 退回重写开篇 |

---

### 维度七：连续问答对检测（v7.0 新增，对应D17增强）

**检测对象**：对话段落中的一问一答对，且问答内容超过70%为设定信息。

**检测算法**：
1. 提取所有对话段落，识别一问一答对（问句+答句相邻）
2. 判定问答内容是否超过70%为设定信息（世界观/规则/背景/技术参数）
3. 统计连续出现的设定问答对次数

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 无连续设定问答对，或≤2轮 | 无需处理 |
| 🟡 黄色 | 连续3-4轮设定问答 | 记录警告，建议改写部分为动作/环境观察 |
| 🔴 红色 | 连续5轮及以上设定问答 | 强制改写——将设定通过角色动作、环境观察或冲突结果间接体现；或将问答改为争执 |

**改写建议**：
- 把"这是什么？""这是XXX技术，原理是YYY" → 改为角色触碰物件时手指被灼伤，读者自己猜
- 把连续问答 → 改为角色间的争执，信息在冲突中泄漏

---

### 维度八：话题悬置审计（v7.0 新增）

**检测对象**：浓缩包 `pending_questions` 字段中标记为"悬置"的问题。

**检测算法**：
1. 读取浓缩包 `pending_questions` 列表
2. 检查每个悬置问题的 `suspended_ch` 字段
3. 计算当前章号 - suspended_ch = 悬置章数

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 悬置章数 ≤ 5章 | 正常，继续追踪 |
| 🟡 黄色 | 悬置章数 6-8章 | 记录警告，提醒下章考虑兑现 |
| 🔴 红色 | 悬置章数 > 8章 | "叙事债务"警告——读者可能忘记或失去耐心 |
| 🔴🔴 严重 | 悬置章数 > 12章 或 问题被遗忘 | 强制在下章兑现或正式放弃（角色明确说"算了，不重要"） |

---

### 维度九：信息包装度检测（v7.2 新增，对应D22）

**检测对象**：所有超过150字的纯叙述者信息传递段落。

**检测算法**：
1. 扫描全章，用自然段划分
2. 识别每个自然段的"信息传递者"：叙述者（全知视角直接告诉读者）还是角色（通过对话/动作/决策传递）
3. 连续"叙述者传递"超过150字 → 黄色警告
4. 同一章出现3处以上黄色警告 → 红色，强制触发信息包装指令1.8.x

**辅助识别关键词**（帮助识别裸奔信息）：
- 数字串（百分之X/X.XX毫米/XX小时/XX公里）+ 解释
- 新专有名词首次出现 + 定义性句子
- 多角色关系/势力 + 说明性句子
- "意味着""说明""原因是""之所以"

**参数连珠炮检测**：grep连续3句以上每句含数字的段落

**阈值与动作**：

| 级别 | 条件 | 动作 |
|:---|:---|:---|
| 🟢 绿色 | 0处裸奔段落 + 0处参数连珠炮 | 无需处理 |
| 🟡 黄色 | 1处裸奔段落 或 1处参数连珠炮 | 记录警告，下一章关注 |
| 🔴 红色 | 2处裸奔段落 或 ≥2处参数连珠炮 | 触发1.8.1 一问一答拆解 |
| 🔴🔴 严重 | 连续2章红色 或 裸奔段落≥3处 | 触发1.8.2 角色中转 + 退回重写 |

## 三、新增七维度检查（D13-D19）与v7.1扩展（D20-D21）及v7.2扩展（D22）

除上述六维度审计外，AI味审计模块同时执行 v6.9 新增7个维度及 v7.1 新增2个维度的量化检查：

### D13 支线缠绕度

**检查方法**：
- 读取浓缩包 `active_subplots` 字段
- 检查每条支线最近10章是否对主线产生推动
- 推动标准：新能力/新盟友/关键资源变化/主线危机升级

**触发**：某支线连续10章累计推动为0 → 触发噪音投放 1.3.x（强制交叉）

### D14 主角道德灰度

**检查方法**：
- 检查最近10章主角行为记录
- 灰度行为类型：情感驱动非理性 / 道德妥协 / 个人牺牲

**触发**：连续10章全为理性最优解 → 触发灰度场景生成（步骤1重写时植入）

### D15 对手智能审计

**检查方法**：
- 检查最近3章对手是否对主角行动做出有效反制
- 对手是否仅被动应对，有无主动布局

**触发**：连续3章对手无有效抵抗 → 触发噪音投放 1.3.2（对手预判）或 1.3.1（第三方介入）

### D16 物象载体

**检查方法**：
- 检查最近5章是否出现具有情感承载力的新物件/细节
- 物象类型：传承物 / 牺牲代价 / 约定印记

**触发**：5章内无新物象 → 触发物象植入指令（步骤1重写时植入）

### D17 设定交代方式

**检查方法**：
- 检测超过200字的设定解释段落
- 检查是否与冲突/伏笔/角色塑造/剧情推动绑定

**触发**：出现超过300字无绑定纯设定 → 标记需改写

### D18 思想锚点

**检查方法**：
- 检查最近5章是否出现核心观点的变体表述

**触发**：10章未出现任何锚点 → 触发思想锚点植入提醒

### D19 开篇方式

**检查方法**：同维度六。

**触发**：以环境描写或设定陈述开篇 → 标记需改写，优先级高

### D20 情感压强审计（v7.1 新增）

**检查方法**：
- 将本章按自然段划分，每单元标注情感压强（L低/M中/H高）
- 计算最大连续H段落数 ÷ 总段落数
- 检测结尾前20%是否有L级换气点

**压强等级定义**：
- **低（L）**：日常描写、环境铺陈、技术说明、非冲突性对话
- **中（M）**：紧张决策、备战、轻度冲突、任务推进
- **高（H）**：直接对抗、重大威胁、时间压力、情绪爆发、死亡风险

**触发**：
- 连续高压段落 > 总段落数×15% → 🟡 黄色警告
- 黄色警告且结尾前无L级段落 → 🔴 红色，触发情感换气指令 1.5.1

### D21 配角辨识度审计（v7.1 新增）

**检查方法**：
- 读取浓缩包 `memory_point_history` 字段
- 检查每个常驻配角最近3次出场的记忆点类型分布
- 记忆点类型：口语习惯 / 标志性动作 / 视觉特征 / 个人史碎片

**触发**：
- 最近3次出场同一类型占比 > 66% → 🟡 黄色警告
- 连续3次出场使用完全相同记忆点 → 🔴 红色，触发记忆点多样化指令 1.6.1

### D22 信息包装度审计（v7.2 新增）

**检查方法**：
- 检测所有超过150字的纯叙述者信息传递段落
- 识别"裸奔信息"：数字串+解释、新专有名词+定义、多角色关系+说明
- 检测参数连珠炮：连续3句以上每句含数字

**触发**：
- 裸奔段落≥2处 或 参数连珠炮≥2处 → 🟡 黄色警告
- 连续2章黄色 或 裸奔段落≥3处 → 🔴 红色，触发1.8.1 一问一答拆解
- 严重情况 → 触发1.8.2 角色中转 + 退回重写

## 四、审计模块增强（v7.1 新增）

### 4.1 关键反转段落感知时长检测

**检测目标**：章节最后10%内容的信息释放速度。

**检测算法**：
1. 识别章节最后10%内容中，首次披露的关键信息点（如新角色登场、敌方计策揭示、重大局势转折）。
2. 统计该信息点数量除以所在段落的总字数，得出"信息释放密度"。
3. 若密度超过阈值（每200字超过1个关键信息点），且总段落数大于3段，则判定为"结尾信息过载"。

**触发动作**：自动激活偏差指令1.4.2【时间拉长】，将最后10%内容按"时间拉长"模块要求进行拆解改写。

### 4.2 比喻密度指数

**检测目标**：本章中明喻与隐喻的出现频率。

**检测算法**：
1. 统计本章正文总字数。
2. 识别并统计所有明喻（如"像……"、"仿佛……"、"如……"等引导词）和隐喻（隐含比较结构）。
3. 计算比喻密度指数 = 比喻总数 ÷ 总字数 × 1000。

**阈值设定**：
- 比喻密度指数 < 8/千字 → 🟢 正常，无需处理
- 比喻密度指数 8-12/千字 → 🟡 黄色，建议在信息强度已足够的段落中替换1-2个比喻为白描
- 比喻密度指数 > 12/千字 → 🔴 红色，强制在改写建议中推荐"留白段落"

## 四、审计报告输出格式

```
============================================
AI味审计报告 - 第X章《章节标题》
审计时间：[时间戳]
============================================

【总体评分】AI味指数：XX/100（越低越好）

【维度一：沉默描述】评分：[绿/黄/红/严重]
```

## 六、与流水线的接口

### 输入
- 文件：编辑版全文（步骤2输出）
- 数据：浓缩包（含 `hook_history`、`active_subplots`、`moral_grayscale_tracker` 等字段）
- 历史：比喻喻体数据库、前5章审计报告

### 输出
- 审计报告：写入 `novel_creator/archives/AI味审计报告/第X章_AI味审计.md`
- 触发指令：记录到自进化日志 + 浓缩包 `deviation_log` 字段
- AI味指数：记录到自进化日志质量趋势表

### 执行时机
步骤2（台词优化）完成后、步骤3（质检）之前。

### 与质检的关系
- AI味审计 ≠ 质检。质检检"写得好不好"，AI味审计检"像不像人写的"。
- AI味审计发现的问题**不阻塞**质检流程。审计报告作为附加输入传给质检Agent。
- 但严重（🔴🔴）级别的问题建议先修复再进质检，否则质检通过的作品仍有明显AI味。
