# SOP v7.2 开发文档

**文档版本**：v1.0  
**编制日期**：2026年5月12日  
**基于版本**：SOP v7.1  
**升级类型**：增量升级（新增维度 + 硬约束执行强化）

---

## 一、升级背景

SOP v7.1在实际执行35章（Ch1-35）后，独立质检暴露出以下系统性问题：

| 问题 | 严重程度 | 影响范围 | 根因分析 |
|------|---------|---------|---------|
| 「不是...是...」对比句式泛滥 | 🔴 P0 | 29/35章超标（83%） | 硬约束执行不严格，grep自动化检测未落实 |
| 跨章重复极度严重 | 🔴 P0 | "指节发白"6次、"摩挲操纵杆"5次 | SOP缺少跨章意象去重机制 |
| 章间衔接断裂 | 🔴 P0 | Ch29→30、Ch30→31、Ch34→35 | SOP未包含章间衔接验证维度 |
| 字数偏离 | 🟡 P1 | 9章偏离（26%） | 工程检查模块（CKP-1/2）失效 |
| AI味审计与质检脱节 | 🟡 P1 | 审计发现问题未强制修复 | 流程设计：审计→修复→质检的阻塞机制缺失 |

v7.2的核心目标：**堵住SOP执行漏洞，强化硬约束的一票否决机制**。

## 二、新增维度定义

### 2.1 新增维度一览

| 维度编号 | 维度名称 | 检查项 | 触发条件 | 偏差指令 |
|---------|---------|--------|---------|---------|
| **D22** | **跨章重复检测** | **关键意象/描写/句式是否在最近10章内重复出现** | **某意象/描写在10章内出现≥3次** | **触发意象冻结指令 + 强制改写** |
| **D23** | **章间衔接验证** | **本章开篇与前章末尾的状态（时间/空间/角色/物品）是否一致** | **时间线矛盾 / 角色状态跳跃 / 物品位置不一致** | **标记需改写，阻塞流程** |

### 2.2 D22：跨章重复检测（v7.2 新增）

**定义**：追踪关键意象、身体描写、标志性动作在跨章范围内的重复频率，防止审美疲劳和AI写作指纹固化。

**检测类别**：

| 类别 | 示例 | 全书上限 |
|------|------|---------|
| **身体反应模板** | "指节发白/泛白"、"拇指摩挲操纵杆"、"眼窝深陷嘴唇干裂" | 每类≤3次/全书 |
| **沉默描写模板** | "没说话"、"没接话"、"嘴唇动了动没出声" | 每类≤5次/全书 |
| **情绪标签** | "心中一紧"、"感到不安"、"松了口气" | 每类≤2次/全书 |
| **环境陈词** | "空气凝固了"、"时间仿佛静止" | 每类≤2次/全书 |
| **句式模板** | "不是...是..."对比结构 | ≤1处/章，≤5处/卷 |

**检测算法**：
1. 维护全书级 `imagery_registry` 注册表，记录以下字段：
   ```json
   {
     "imagery_id": "knuckles_white",
     "description": "指节发白/泛白",
     "category": "身体反应模板",
     "occurrences": [
       {"chapter": 20, "line": 45, "context": "陆川握紧操纵杆，指节泛白。"},
       {"chapter": 22, "line": 112, "context": "他指节发白地攥着数据板。"},
       {"chapter": 23, "line": 78, "context": "蝰蛇指节发白。"}
     ],
     "count": 3,
     "status": "冻结"  // active / warning / frozen
   }
   ```
2. 每章完成后，提取本章所有身体描写、沉默描写、情绪标签、环境描写。
3. 与 `imagery_registry` 比对相似度（语义匹配+关键词匹配）。
4. 更新注册表，标记状态：
   - `active`：出现1-2次，正常使用
   - `warning`：出现3次，黄色警告，下章避免
   - `frozen`：出现≥4次，红色冻结，**全书禁用**

**阈值设定**：
- 某意象在10章窗口内出现3次 → 🟡 黄色警告
- 某意象在10章窗口内出现≥4次 或 全书累计≥上限 → 🔴 红色冻结

**触发动作**：
- 黄色：下章自动提醒"避免使用[意象名]"，推荐替代写法
- 红色：**强制改写**，将该意象替换为白描或动作呈现，否则**阻塞质检流程**

**替代写法库（示例）**：
| 冻结意象 | 替代写法 |
|---------|---------|
| "指节发白" | "指甲陷进掌心"、"虎口青筋凸起"、"指关节咔哒响了一声" |
| "拇指摩挲操纵杆" | "食指敲击操纵杆侧面"、"手掌在操纵杆上转了个角度"、"小指勾住操纵杆底部" |
| "眼窝深陷嘴唇干裂" | "眼下青黑"、"嘴角起皮"、"眼眶发红" |
| "没说话" | "喉结动了一下"、"呼吸重了一拍"、"视线移开" |

### 2.3 D23：章间衔接验证（v7.2 新增）

**定义**：验证本章开篇与前章末尾在时间、空间、角色状态、关键物品上的一致性，防止断裂感。

**验证维度**：

| 维度 | 检查项 | 不一致示例 |
|------|--------|-----------|
| **时间线** | 本章开篇时间是否紧接前章末尾 | Ch34已完成七跳准备第八跳，Ch35却回到"波赫文七跳之外"讨论 |
| **空间位置** | 角色物理位置是否合理过渡 | Ch30全队回站，Ch31蝰蛇独自在废弃层被刺，缺少过渡 |
| **角色状态** | 伤势/情绪/装备状态是否延续 | Ch9陆川眉毛焦了半条，Ch10未提及恢复 |
| **关键物品** | 物品位置/状态是否一致 | Ch24解码器在蝰蛇处，Ch25却在陆川桌上 |
| **倒计时/时限** | 前章设定的时限是否在本章延续 | Ch29设定48小时时限，Ch30直接跳到开战 |

**检测算法**：
1. 读取前章浓缩包 `chapter_end_state` 字段：
   ```json
   {
     "chapter": 34,
     "end_state": {
       "time": "完成七跳，准备第八跳",
       "location": "第八跳起点，茶隼级编队",
       "characters": {
         "陆川": {"status": "指挥状态", "injury": "无", "location": "旗舰"},
         "蝰蛇": {"status": "待命", "location": "僚机"}
       },
       "key_items": {
         "解码器": {"location": "蝰蛇处", "status": "已解码"},
         "石鸦号坐标": {"location": "导航仪", "status": "已输入"}
       },
       "pending_deadline": "48小时倒计时进行中"
     }
   }
   ```
2. 读取本章开篇前500字，提取状态信息。
3. 逐项比对，标记不一致项。

**阈值设定**：
- 任一维度不一致 → 🔴 红色，**阻塞流程**

**触发动作**：
- 红色：**强制要求修复**，在章节开头增加过渡段落或调整场景，否则**无法进入质检**
- 修复方式：
  - 时间线矛盾：增加"X小时后"或调整场景顺序
  - 空间跳跃：增加过渡场景（航行/等待/准备）
  - 状态未延续：补充伤势/情绪描写
  - 物品位置：明确交接或转移过程

## 三、硬约束执行强化（v7.2 核心升级）

### 3.1 问题根因

v7.1的硬约束执行存在**系统性漏洞**：

| 硬约束 | SOP规定 | 实际执行 | 漏洞 |
|--------|---------|---------|------|
| 「不是...是...」≤1处/章 | grep+人工复核 | 仅人工复核，grep未落实 | 自动化检测缺失 |
| 字数3000-3500 | CKP-1验证 | CKP-1未执行 | 工程检查失效 |
| 章末钩子 | 质检检查 | 基本达标 | ✓ 执行较好 |
| AI收束结尾 | 质检检查 | 基本达标 | ✓ 执行较好 |

### 3.2 v7.2 强化措施

#### 措施1：硬约束自动化检测（步骤2.5增强）

在AI味审计（步骤2.5）中增加**硬约束自动化检测子步骤**：

```
步骤2.5 AI味审计
  ├── 2.5.1 八维度审计（原有）
  ├── 2.5.2 D13-D21审计（原有）
  ├── 2.5.3 审计增强（原有）
  └── 2.5.4 硬约束自动化检测（v7.2 新增）
       ├── grep「不是...是...」→ 计数
       ├── wc -m 字数统计 → 验证3000-3500
       ├── 章末200字提取 → 人工确认钩子
       └── 输出：硬约束检测报告
```

**硬约束检测报告格式**：
```
硬约束自动化检测报告 - 第X章
================================
1. 「不是...是...」对比句式：X处（阈值≤1）【通过/不通过】
2. 字数统计：XXXX字（阈值3000-3500）【通过/不通过】
3. 章末钩子检测：【有/无】
4. AI收束结尾检测：【有/无】
5. EVE Lore违规：X处
================================
硬约束总评：【全部通过 / X项不通过】
```

**一票否决机制**：
- 任一硬约束不通过 → **阻塞流程**，返回步骤1（主笔）或步骤2（台词优化）修复
- **不允许进入步骤3（质检）**

#### 措施2：D22+D23前置阻塞（步骤2.5增强）

将D22（跨章重复）和D23（章间衔接）纳入步骤2.5，作为**前置阻塞条件**：

```
步骤2.5 AI味审计（v7.2 完整流程）
├── A. 单章维度审计（D1-D21）
├── B. 跨章维度审计（v7.2 新增）
│   ├── D22 跨章重复检测
│   │   └── 触发冻结意象 → 强制改写 → 重新审计
│   └── D23 章间衔接验证
│       └── 发现不一致 → 强制修复 → 重新验证
├── C. 硬约束自动化检测
│   └── 任一不通过 → 阻塞流程
└── D. 输出审计报告
```

#### 措施3：质检Agent输入增强

质检Agent（novel-quality-reviewer）的输入增加**硬约束检测报告**和**D22/D23审计报告**：

```yaml
输入：
  - 编辑版章节正文
  - AI味审计报告（含D1-D21）
  - 硬约束检测报告（v7.2 新增）
  - D22跨章重复报告（v7.2 新增）
  - D23章间衔接报告（v7.2 新增）
  - 写作偏好_共享.md
```

质检Agent的评分标准调整：
| 维度 | v7.1 分值 | v7.2 分值 | 调整理由 |
|------|----------|----------|---------|
| 禁止事项 | 15分 | **25分** | 硬约束一票否决，分值提升 |
| 文笔五律 | 25分 | 20分 | |
| 情节节奏 | 20分 | 20分 | |
| 人物塑造 | 15分 | 15分 | |
| 格式合规 | 10分 | 10分 | |
| EVE Lore | 15分 | 10分 | |

**质检通过条件（v7.2）**：
- 硬约束检测报告：全部通过（一票否决）
- D22报告：无冻结意象（一票否决）
- D23报告：无衔接断裂（一票否决）
- 质检评分：≥91分

## 五、偏差指令库升级（v7.2）

### 5.1 新增指令组：1.7 意象替代指令组

**目标**：当D22触发冻结意象时，提供强制替代方案。

| 模块 | 名称 | 触发条件 | 核心规则 |
|:---|:---|:---|:---|
| **1.7.1** | **身体反应替代** | "指节发白"等身体反应模板被冻结 | 从替代库随机选择：指甲陷进掌心/虎口青筋凸起/指关节咔哒响/掌心出汗黏腻/手腕僵硬 |
| **1.7.2** | **沉默描写替代** | "没说话"等沉默模板被冻结 | 从替代库随机选择：喉结动了一下/呼吸重了一拍/视线移开/肩膀微不可察地绷紧/手指无意识敲击 |
| **1.7.3** | **句式结构替代** | "不是...是..."超限 | 强制改写为白描或动作呈现，禁止对比结构 |

## 六、实施计划

v7.2的实施分两个阶段：

### 阶段一：修复现有35章（立即执行）

1. **D22清洗**：全书grep扫描「不是...是...」、"指节发白"、"拇指摩挲"等冻结意象，逐章改写
2. **D23修复**：修复Ch29→30、Ch30→31、Ch34→35的衔接断裂
3. **字数调整**：Ch5/Ch17精简，Ch33/Ch34扩展
4. **Ch24补全**：补全截断内容

### 阶段二：v7.2流程固化（下一卷启动时）

1. 更新SOP文档至v7.2
2. 更新AI味审计模块（增加2.5.4硬约束检测、D22、D23）
3. 部署 `imagery_registry` 全局追踪
4. 更新质检Agent输入模板
5. 下一卷（Ch36+）启用v7.2完整流程
